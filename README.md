# 植物管理アプリ(PWA)

ビルド不要の静的Webアプリです(HTML/CSS/JavaScript のみ)。データはブラウザ内(IndexedDB)に保存され、サーバーには送られません。

## 起動・公開
- **試すだけ**: このフォルダで `python3 -m http.server 8000` → http://localhost:8000
- **スマホでも使う**: フォルダ全体を HTTPS の静的ホスティング(GitHub Pages など)に置きます。PWA・通知・Service Worker は HTTPS(または localhost)でのみ動作します。`index.html` を直接開いても画面は出ますが、保存・通知は不安定です。
- スマホのブラウザで「ホーム画面に追加」するとアプリとして使えます(Android は Chrome、iPhone は Safari)。
- GitHub Pages の1回のアップロードは100ファイル未満です。素材が多いので `upload-1_本体` と `upload-2_イラスト` に分けて配布しています。
- `植物管理アプリ_使い方ガイド.pdf` を `index.html` と同じ場所に置くと、アプリ(設定・初回起動時)からダウンロードできます。

## 画面構成(下のタブ)
ホーム / ライブラリー / 水やり / カレンダー / 用土 / メモリアル。右上に ライト・ダーク切替 と 設定 があります。
- **ホーム**: 今日のお世話、7日以内の予定、天気と温度警告、今月のヒント。
- **ライブラリー**: 植物の一覧(大・中・小・リスト)、登録・編集、詳細(ケア/情報/履歴)。種類(ライブラリー共通の情報)と個体(1株ごと)を分けて管理します。
- **水やり**: 「スケジュール」(予定日順にチェックで記録、液肥はスキップ可)と「今日水やりした植物/今日液肥をあげた植物」(予定のない植物をまとめて記録)。液肥を記録すると水やりも同時に記録されます。
- **カレンダー**: 月間/年間、成長サイクル、植物の絞り込み。
- **用土**: 配合レシピと用土の種類の管理(植え替えの記録で使用)。
- **メモリアル**: 枯れた植物を、履歴・写真つきで記録として残します(「所持植物に戻す」も可能)。 詳細を開くたびに「水が好きだった…」などの**ひとことがランダム表示**されます。「墓石に思い出を刻む」で自由入力すると、その言葉が固定表示になります(`graves.epitaph` に保存、バックアップ対象)。ランダム表示の言葉は 設定 →「墓石のひとこと(おまけ)」で追加・編集・削除・初期化できます(`kv: epitaphCfg` に保存)。

## 設定(各項目は開閉式で、状態を記憶します)
表示 / アプリとしてインストール(診断) / ネット検索・AI / 地域 / 温度警告 / 水やり・液肥の予定と通知 / バックアップ・復元 / アプリの更新・キャッシュ / 使い方ガイド / アプリのアイコン(ライブラリーの写真をアイコンにするおまけ機能つき。画面・タブはすぐ反映、ホーム画面のアイコンは「削除→追加し直し」で反映。ブラウザの manifest を一時的に差し替えて実現)。

## 主な仕様
- **温度警告**: Open-Meteo(APIキー不要・無料)の週間予報を使用。温度は設定画面で全植物共通。「屋外管理の最低温度」を下回る日/「高温注意温度」以上の日は、種類・屋内外に関係なく「特に寒い/暑い」と表示し、その間は他の気温警告を出しません。通常の「室内取り込み目安」警告は屋外の植物だけが対象です(屋内の植物は対象外、場所未設定は屋外扱い)。オフライン時は前回取得分を表示します。
- **予定の表示**: 水やり・液肥の予定日が近づく/過ぎると「そろそろ→カラカラ→み、水…」(液肥は「そろそろ→腹ペコ→断食」)などの言葉で表示。言葉は設定で変更可能。
- **通知**: 設定で許可・時刻・段階(そろそろ/最適/予定を過ぎてる)を選択。液肥は成長期のみ。アプリを開いた時/画面に戻った時に判定します(確実)。閉じたままの通知は「定期バックグラウンド同期」に対応した環境(ホーム画面に追加した Chrome/Android など)のみで、時刻は保証されません。iOS Safari は非対応の場合があります。時刻どおりの確実なプッシュ通知には Web Push サーバーが必要で、未実装です。
- **オフライン**: 一度開いたあとは Service Worker のキャッシュで画面が開きます(新しい版があるときはネット接続時に自動更新。設定の「更新を確認」「キャッシュを消して再読み込み」でも操作可能)。天気・AI検索はネット接続が必要です。
- **AI自動入力(任意)**: 設定で Gemini APIキーを登録すると、種類の情報を自動入力できます。キーはこの端末のブラウザ内にだけ保存され、AIへの問い合わせ時にGoogleへ送られます。**バックアップには含まれません**(復元後に再入力)。Google検索・AIモードでの調べものはキー不要です。
- **購入時期と享年**: 購入時期は 年→季節→月(季節の範囲)→日 の順に入力します。日が分からないときは「月前半(7日扱い)」「月後半(21日扱い)」を選びます(記録には「約」と表示)。享年は購入日(または基準日)から枯死日までを暦で数え、1年以上は「享年◯歳(◯日)」、1年未満は「◯ヶ月(◯日)」と表示します。枯死日は購入時期より前・未来の日付にできません。冬の月は、その年の12月・1月・2月から選びます。

## バックアップ・復元
- 設定 →「バックアップを保存」で JSON(画像込み)をダウンロード。定期保存を推奨します(最後の保存から3か月でお知らせ)。
- 復元は、ファイルの形式・必須項目を**検証してから**、全データを**1回の処理でまとめて**置き換えます。途中で失敗しても一部だけ復元されることはありません(失敗時は現在のデータのまま)。
- 復元の前に、いまのデータを `plant-backup-before-restore-日付.json` として自動保存します。復元後は件数を確認します。
- 旧バージョンのバックアップ(`version` なし・一部のデータのみ)も読み込めます。ファイルに含まれないデータ(例: 配合レシピ)は現在のものを残します。

## 構成
`js/core.js` 日付・次回予定・温度警告・通知判定(ページと Service Worker 共通) / `db.js` 保存(IndexedDB・復元の検証) / `data.js` 記録・メモリアル移動 / `plants.js` ライブラリー / `tasks.js` / `calendar.js` / `soil.js` / `memorial.js` / `home.js` / `settings.js` / `weather.js` / `notify.js` / `search.js` / `pwa.js` / `guide.js` / `appicon.js` / `ui.js` / `theme.js` / `sw.js`
`assets/sprites` はイラスト素材、`assets/grave.svg` はお墓の画像です。素材シート(`sheets`)はアプリから参照されないため、配布物には含めていません。

## 保存データ(IndexedDB `plantkeeper`)
species / plants / logs / repots / materials / recipes / graves / kv(設定ほか)。画像は dataURL としてレコード内に保存します。データ構造の変更はなく、以前のデータ・バックアップがそのまま使えます。
